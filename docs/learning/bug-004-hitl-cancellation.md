# Bug 004：取消工单后，模型仍要求再次确认

## 现象

DeepSeek 已发起 `create_support_ticket`，系统暂停等待确认。
用户回复“取消”后，MySQL 没有写入，但模型仍可能回复“请确认后我将为您提交”。
这会让用户无法确定申请是否已取消。

## 根因

Human-in-the-loop 中间件把拒绝决定变成一个 `status=error` 的 ToolMessage：
“用户未明确确认或已取消，本次写操作未执行。”
Agent 随后仍调用模型生成回复，模型可能把这个结果理解为“缺少确认”，再次询问。

同时调用查询和创建工具时，最后一个消息还可能是查询结果，不能仅检查最后一条消息。

## 修复

在 `deterministic_tool_routing` 中检查当前末尾连续的工具结果。
仅当工具名是 `create_support_ticket`、状态是 error、内容是系统产生的拒绝提示时，
直接生成“本次工单申请已取消，未创建工单。”，结束本次执行，不再调用模型。

遇到非工具消息就停止向前查找，避免旧取消记录影响用户后续的问题。
普通工具错误和批准后的写入仍走原有流程。

## 验证

- 回归测试在修复前失败，分别覆盖单个工单调用和查询、工单混合调用。
- 验证取消后的最终消息、无待恢复任务、数据库没有工单写入。
- 全量测试 175 项通过，2 项原有模拟 Docker 集成测试跳过。
- 更新容器后，用真实接口触发工单，再通过 SSE 回复“取消”：
  返回明确取消提示，数据库无写入，同一对话还能继续查询订单。

完整在线验收结果在 `data/evaluation/online_acceptance_siliconflow.json`。
